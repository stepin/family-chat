# M0: проверка на своём роутере и телефонах

M0 отвечает на один вопрос: в каком режиме семья будет работать (`docs/PLAN.md`, раздел 9). Код для этого готов:
зонд сервера (`/probe/`) и проверка устройства (`/device/`). Остальное проверяется руками по списку ниже.

## 1. Что подготовить

1. **Папку и учётную запись на роутере.** Папка, например `family-chat`, и отдельная учётная запись WebDAV с доступом
   только к ней. Пароль простой для теста, потом его можно сменить.
2. **Клиент на его будущем адресе.** Зонд проверяет CORS для того адреса, с которого открыт, поэтому запускать его надо
   с адреса клиента, а не откуда-нибудь. Соберите и выложите клиент на свой домен:

   ```bash
   git clone https://github.com/stepin/family-chat.git
   cd family-chat
   pnpm install
   pnpm build
   ```

   Содержимое `apps/web/dist/` выкладывается на хостинг как есть (сборка не зависит от пути). Нужен HTTPS.

   Для первой пробы с ноутбука можно обойтись без хостинга: `pnpm --filter @family-chat/web preview` и
   `http://localhost:4173/probe/` в браузере на том же ноутбуке. Адрес клиента тогда `http://localhost:4173`, и в
   рецептах прокси надо указать именно его. С телефонов так проверить нельзя: нужен HTTPS.

## 2. Зонд сервера

1. Откройте `https://<адрес клиента>/probe/`, введите адрес папки (со слешем в конце), логин и пароль, нажмите
   «Проверить сервер».
2. Вердикт:
   - «Сервер подходит»: режим A на штатном WebDAV.
   - «Нужна настройка сервера»: у WebDAV нет CORS (или он не открывает `Date`, или не ставит CORS на ошибки). Поставьте
     рядом Caddy или nginx по [`docs/recipes`](recipes/README.md) и запустите зонд ещё раз уже с адресом прокси.
   - «Не подходит»: причина написана под вердиктом. Неверный пароль тоже даёт этот вердикт: сервер, который требует
     Digest, отвечает так же.
3. Нажмите «Скопировать отчёт» (или «Скачать отчёт»). Пароля в отчёте нет, но есть адрес сервера и логин: не
   выкладывайте его публично.

Зонд создаёт папку `fc-probe-…`, пишет в неё файлы (в том числе 5 МБ) и удаляет. Если проверка оборвалась, папку можно
удалить руками.

Повторите зонд:

- с ноутбука;
- с iPhone в Safari и с Android в Chrome, дома по Wi-Fi;
- с тех же телефонов в мобильной сети (Wi-Fi выключен).

## 3. Проверка устройства

На каждом телефоне откройте `https://<адрес клиента>/device/`, нажмите «Проверить устройство», скопируйте отчёт.
На iPhone дважды: в Safari и из установленного приложения (см. ниже). Страница проверяет OPFS (из страницы и из
воркера), IndexedDB, постоянное хранилище, кодирование WebP и JPEG, уменьшение через `createImageBitmap`, наличие
Periodic Background Sync, уведомлений, Web Locks и разрешения на доступ к локальной сети.

## 4. Ручные проверки

Код их не покрывает. Для каждой запишите результат: работает, не работает, что видно на экране.

| # | Проверка | Как |
|---|---|---|
| 1 | Установка PWA на iOS | Safari → `https://<адрес клиента>/` → «Поделиться» → «На экран Домой». Открыть с экрана Домой: окно без адресной строки? Запустить оттуда зонд. |
| 2 | Установка PWA на Android | Chrome → тот же адрес → «Установить приложение». Открыть со значка, запустить зонд. |
| 3 | Доступ из мобильной сети | Зонд с телефона без Wi-Fi. Если адрес роутера доступен только дома, это видно здесь. |
| 4 | Поведение после простоя | Не открывать установленное приложение 3-5 дней, затем открыть и сразу запустить зонд. Открылось ли оно без сети в первые секунды, прошёл ли зонд, не пришлось ли что-то вводить заново кроме пароля. |
| 5 | Доступ к локальной сети в Chrome | Дома по Wi-Fi, Chrome на Android и на компьютере. Если имя роутера дома разрешается в адрес 192.168.x.x, Chrome спросит разрешение на доступ к устройствам в локальной сети. Было ли окно, что в нём написано, что будет при отказе (зонд покажет «Сервер не отвечает» и состояние разрешения в отчёте). |
| 6 | OPFS и кодирование картинок на iOS | Отчёт страницы `/device/` из Safari и из установленного приложения. Нужны строки OPFS, WebP, JPEG, `createImageBitmap`. |
| 7 | Сохранение данных на iOS | После пункта 4 открыть `/device/`: строка «Постоянное хранилище» и объём занятого места. |
| 8 | Раскрутка диска | Если на роутере USB-диск с засыпанием: слышно или видно ли, что он просыпается при каждом запуске зонда. Включено ли засыпание в настройках роутера. |
| 9 | Файловая система накопителя | Какая (exFAT, NTFS, ext4) и какой размер кластера: от этого зависит место под бессрочный журнал, если роутер не сообщает свободное место. |
| 10 | Клиент и WebDAV на одном домашнем устройстве | Только если хостинг клиента не нужен: два имени на одном устройстве (`docs/recipes/README.md`, последний раздел), зонд с телефона. |

Что M0 из раздела 9 плана пока не проверить без клиента M1: реальная частота Periodic Background Sync, сохранение
приглашения при установке на iOS через `start_url`, CSP воркера и service worker на выбранном хостинге, запросы из
воркера при запросе доступа к локальной сети, цена предварительных запросов на полной первой синхронизации (зонд
даёт только оценку одного запроса). Их стоит отметить в отчёте как непроверенные.

## 5. Что прислать

1. Отчёты зонда: ноутбук, каждый телефон дома и в мобильной сети, и после настройки прокси, если она понадобилась.
2. Отчёты `/device/` с каждого телефона (на iPhone из Safari и из установленного приложения).
3. Таблицу из раздела 4 с результатами.
4. Модель роутера и версию прошивки; как сделан HTTPS (KeenDNS, DDNS и Let's Encrypt, другое); где стоит прокси, если
   он нужен.
5. Выбор исхода:
   - режим A на штатном WebDAV;
   - режим A через сервер или прокси с CORS;
   - режим B, если режим A недостижим и вы осознанно соглашаетесь на уровень без защиты от участников
     (`docs/PLAN.md`, разделы 3 и 5);
   - остановка перед M1.

Сырые ответы сервера из отчётов зонда станут образцами для `tools/dav-dev` в M1.
