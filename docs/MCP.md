# ИИ-помощники (MCP)

К семейному чату можно подключить ИИ-помощника, например Claude. Он подключается по протоколу
[MCP](https://modelcontextprotocol.io/) и делает то же, что человек в приложении: читает и пишет сообщения, ведёт
группы, отправляет файлы. Всё это встроено в `fcd`: отдельной программы, плагина или второго процесса нет.

## Сначала о доверии

Обычно сервер семьи не может прочитать переписку: ключи есть только на устройствах. Подключение ИИ-помощника это
осознанное исключение.

- Чтобы действовать за личность, **сервер хранит её ключ**. Он может читать переписку этой личности и писать от её
  имени. То же может тот, кто управляет сервером или получил копию папки данных.
- Это касается только подключённых личностей. Переписка остальных участников между собой остаётся закрытой от
  сервера, как и раньше.
- Собеседники это видят: в профиле участника, к личности которого подключён помощник, приложение показывает
  пометку.
- Тексты сообщений попадают к ИИ-помощнику и к тому, кто его предоставляет. Что он с ними делает, решают его
  правила, а не Family Chat.

Подробнее: [безопасность](SECURITY-MODEL.md#ии-помощники-mcp).

## Два вида подключений

| | Помощник со своей личностью | Моя личность |
|---|---|---|
| Кто создаёт | администратор семьи | любой участник, для себя |
| Чьим именем пишет | своим: у него своё имя и свой профиль | вашим: родственники не отличат его сообщения от ваших |
| Что видит | свои чаты: то, что пишут ему и в группах, куда его добавили | всю вашу переписку в этой семье, пока она лежит на сервере |
| Ключ | создаётся на сервере и нигде больше не существует | приложение отправляет серверу ключ вашей личности (то же, что 24 слова) |
| Удаление | помощник исключается из семьи | сервер стирает ключ, вы остаётесь в семье |

Помощник со своей личностью: обычный участник семьи. Ему можно написать, его можно добавить в группу, он может
создать свою. Это безопасный вариант по умолчанию: он видит только то, что ему показали.

Подключений может быть несколько, у каждого свой токен и свои разрешения. Предел: 50 на семью.

## Как подключить

1. В приложении: **Настройки → ИИ-помощники**.
2. Администратор: введите имя и нажмите «Создать помощника». Любой участник: «Подключить мою личность…», прочитайте
   предупреждение и подтвердите.
3. Приложение покажет **адрес** и **токен**. Токен показывается один раз: приложение его не хранит. Потеряли:
   нажмите «Новый токен», старый сразу перестанет работать.
4. Перенесите адрес и токен в настройки ИИ-помощника.

Адрес: `https://<сервер>/mcp`, для семьи по адресу `/f/<id>`: `https://<сервер>/f/<id>/mcp`.

Claude Code:

```sh
claude mcp add --transport http family-chat https://chat.example.org/mcp \
  --header "Authorization: Bearer fcm_…"
```

Клиенты с файлом настроек (поле может называться иначе, смотрите документацию клиента):

```json
{
  "mcpServers": {
    "family-chat": {
      "type": "http",
      "url": "https://chat.example.org/mcp",
      "headers": { "Authorization": "Bearer fcm_…" }
    }
  }
}
```

Нужен клиент, который умеет MCP по HTTP («Streamable HTTP») и позволяет задать заголовок `Authorization`. Вход через
OAuth не поддерживается ([TODOS.md](../TODOS.md)). Локальной программы для stdio нет: помощник обращается к серверу
семьи по сети, как и приложение.

Токен работает без пароля. Храните его как пароль: не вставляйте в чат с помощником и в общие файлы. Если токен
попал не туда, удалите подключение или выпустите новый токен.

## Что разрешено

Разрешения задаёт человек в приложении, по каждому подключению отдельно. Через MCP их изменить нельзя: такого
инструмента нет.

| Уровень | Что даёт | По умолчанию |
|---|---|---|
| Чтение (`read`) | чаты, сообщения, список семьи, поиск, ожидание новых сообщений | включён |
| Запись (`write`) | сообщения, правки, реакции, стикеры, группы, профиль, «удалить у меня» | включён |
| Файлы (`files`) | отправка и получение файлов и фотографий, аватар | выключен |
| Администрирование (`admin`) | приглашения и сведения о сервере; работает, только если личность администратор семьи | выключен |
| Необратимое (`destructive`) | «удалить у всех»; вместе с администрированием исключение участников | выключен |

Помощник видит в списке только инструменты разрешённых уровней. Вызов запрещённого возвращает ошибку `level_off` с
объяснением, где это включить.

## Инструменты

Чаты называются идентификатором из `chats_list` или идентификатором участника из `members_list` (личный чат с ним;
свой идентификатор это «Избранное»). Сообщения называются числом из `messages_list`.

| Инструмент | Уровень | Что делает |
|---|---|---|
| `whoami` | чтение | за кого действует подключение, его разрешения, имя семьи, пределы сервера |
| `members_list` | чтение | участники семьи |
| `member_avatar_get` | чтение | аватар участника |
| `chats_list` | чтение | чаты с последним сообщением |
| `messages_list` | чтение | сообщения чата с правками, реакциями и удалениями |
| `messages_search` | чтение | поиск по тексту и именам файлов |
| `events_wait` | чтение | ждёт новое: сообщение, правку, реакцию, удаление, изменение группы |
| `group_info` | чтение | название, владелец и состав группы |
| `stickers_list` | чтение | наборы стикеров семьи |
| `message_send` | запись | текст, ответ на сообщение, место |
| `message_edit` | запись | правка своего сообщения |
| `message_react` | запись | реакция и её снятие |
| `message_delete` | запись | «удалить у меня»; `for_everyone` требует уровня «необратимое» |
| `message_forward` | запись | пересылка в другой чат (с файлами нужен уровень «файлы») |
| `sticker_send` | запись | стикер из набора семьи |
| `profile_update` | запись | имя и род, удаление аватара |
| `group_create` | запись | новая группа |
| `group_rename`, `group_members_add`, `group_members_remove`, `group_transfer` | запись | для владельца группы |
| `group_leave` | запись | выход из группы; владелец сначала передаёт её |
| `file_send` | файлы | отправка файла или фото |
| `file_get` | файлы | получение файла |
| `file_upload_start` | файлы | одноразовая ссылка для большого файла |
| `profile_avatar_set` | файлы | аватар |
| `invite_create`, `invites_list`, `invite_delete` | администрирование | приглашения |
| `server_stats` | администрирование | участники, чаты, место на диске |
| `member_remove` | администрирование и необратимое | исключение участника |

У каждого инструмента есть описание и схема аргументов: помощник получает их сам запросом `tools/list`.

### Новые сообщения

Сервер не пишет помощнику первым. Чтобы узнавать о новом, помощник вызывает `events_wait`: запрос ждёт до 50 секунд
(по умолчанию 25) и возвращает события и курсор; курсор передаётся в следующий вызов. Без курсора вызов ждёт то, что
случится с этого момента. То, что отправило само подключение, не возвращается.

Помощник отвечает, только пока его сеанс открыт и он сам вызывает `events_wait`. Ответов «сам по себе», когда
сеанса нет, пока нет ([TODOS.md](../TODOS.md)).

### Файлы

- До 1 МБ файл передаётся прямо в вызове: `file_send` принимает его в base64, `file_get` возвращает картинку как
  картинку, текст как текст, остальное в base64.
- Больше: `file_upload_start` даёт одноразовую ссылку, на неё файл отправляется запросом `PUT`, затем `file_send` с
  полученным значением `upload`. Большой файл `file_get` тоже отдаёт ссылкой.
- Ссылка `…/mcp/files/<код>` работает один раз, 10 минут, без токена: секрет это сам код. Одновременно не больше
  четырёх неиспользованных ссылок на загрузку у одного подключения. Предел размера: `max_file_mb` сервера.
- Фотографии (JPEG, PNG, WebP, GIF) распознаются по содержимому. Перед отправкой из них убираются метаданные: место
  и время съёмки, модель камеры, комментарии. Поворот снимка сохраняется. `original: true` отправляет файл как есть.
- Картинки не уменьшаются, миниатюра не создаётся: сервер не декодирует изображения. Собеседники увидят фото после
  загрузки.

## Что помощник не может

Список намеренный. Каждое «нет» записано в `server/src/mcp/coverage.rs` рядом с причиной, и тест следит, чтобы у
новой возможности приложения появился либо инструмент, либо причина.

- **Создать, перенести или отозвать личность, увидеть 24 слова.** Это делает человек в приложении: слова не проходят
  через модель.
- **Управлять подключениями и разрешениями.** Только в приложении.
- **Читать то, чего нет на сервере.** Помощник видит переписку за срок хранения (`retention_days`); архива на
  устройстве у него нет.
- **Читать чужие чаты.** Только чаты своей личности. В группе, куда его добавили «без прежней переписки», прежнего
  не видно.
- **Голосовые сообщения.** Аудиофайл отправляется обычным файлом.
- **Создавать наборы стикеров.** Их делают в приложении; помощник отправляет стикеры из готовых.
- **Уведомления.** Они для устройств с экраном.

## Настройка сервера

MCP включён по умолчанию. Выключить: `--mcp false`, `FCD_MCP=false` или `mcp = false` в `config.toml`, затем
перезапуск. Тогда `/mcp` и экран в приложении отвечают, что подключение выключено; созданные подключения остаются на
диске и заработают, если включить снова. Пока ни одного подключения нет, сервер не хранит ничьих ключей.

Что учесть за обратным прокси:

- Запросы `events_wait` длятся до 50 секунд: время ожидания ответа у прокси должно быть больше (как и для
  приложения).
- Прокси должен передавать `Host` и `X-Forwarded-Proto` (или `X-Forwarded-Host`): из них сервер строит одноразовые
  ссылки на файлы.
- Тело запроса `/mcp` до 2 МБ; файл по ссылке до `max_file_mb`.

Ключи подключений лежат в папке данных, в `mcp/`. Резервная копия папки данных теперь содержит ключи подключённых
личностей: храните её так же бережно, как сам сервер.

## Для разработчиков

- Транспорт: MCP поверх HTTP, один запрос `POST` на сообщение, ответ одним JSON. Потоков (SSE) и сеансов нет; `GET`
  и `DELETE` отвечают 405.
- Ревизии: `2026-07-28` (без рукопожатия, версия в каждом запросе и в заголовках `MCP-Protocol-Version`,
  `Mcp-Method`, `Mcp-Name`) и прежние `2025-11-25`, `2025-06-18`, `2025-03-26` (с `initialize`).
- Вход: `Authorization: Bearer <токен>`. Сервер хранит только SHA-256 токена. Неверный токен: 401; десять неверных
  за минуту с одного адреса: 429 (счётчик общий с неверными кодами, [API](API.md#15-ограничение-частоты)).
  Личность исключена или отозвана: 403 `identity_gone`. MCP выключен: 404 `mcp_disabled`.
- Запрос с заголовком `Origin` другого сайта отклоняется (403 `bad_origin`); заголовков CORS у `/mcp` нет.
- Ошибка инструмента возвращается внутри результата (`isError: true`) как `{"error": "<код>", "message": "…"}`:
  модель читает причину и исправляется. Неизвестный инструмент: ошибка JSON-RPC `-32602`.
- Сервер действует за личность второй реализацией протокола, на Rust (`server/src/client/`), сверенной с
  `docs/vectors/`. Изменение протокола меняет обе реализации и векторы
  ([CONTRIBUTING.md](../CONTRIBUTING.md#изменения-протокола-и-тестовые-векторы)).
- Запросы приложения для управления подключениями: [API, раздел 10b](API.md#10b-подключения-mcp).

## Если не работает

| Что видно | Что это значит |
|---|---|
| 401 | токен неверный или заменён новым. Выпустите новый в приложении |
| 403 `identity_gone` | личность подключения исключена из семьи или отозвала ключ |
| 404 `mcp_disabled` | MCP выключен в настройках сервера |
| 404 у ссылки на файл | ссылка использована, просрочена (10 минут) или сервер перезапускался |
| 429 | слишком много неверных токенов или кодов с этого адреса, подождите минуту |
| `level_off` | уровень выключен: включите его в приложении, «Настройки → ИИ-помощники» |
| `need_key` у группы | у личности нет ключа текущей эпохи группы: владелец группы должен добавить её заново |
| ссылка на файл с `http://` вместо `https://` | прокси не передаёт `X-Forwarded-Proto` |
