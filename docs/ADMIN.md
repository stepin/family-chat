# Установка сервера

Эта страница для администратора: того, кто запускает сервер `fcd` для своей семьи. Нужно уметь открыть терминал и
выполнить несколько команд. Что делать остальным членам семьи, написано в [памятке для семьи](FAMILY.md).

## Что понадобится

- **Компьютер, который работает круглосуточно**: мини-ПК, NAS, Raspberry Pi, домашний сервер или VPS. Сервер это
  одна программа `fcd` и одна папка с данными, базы данных нет. Памяти ему нужно немного.
- **HTTPS с настоящим сертификатом.** Браузер без HTTPS не даст приложению шифровать, присылать уведомления и
  устанавливаться на экран телефона. Чаще всего HTTPS даёт обратный прокси (раздел [HTTPS](#https)).
- **Доступ из интернета**, если родственники будут писать не только из дома: проброс порта на роутере, VPS или туннель.
- **Место на диске.** Текст занимает мало; место определяют фото и файлы за срок хранения (по умолчанию 90 дней).

## Скачать

Готовые файлы публикуются на странице выпусков: https://github.com/stepin/family-chat/releases. Рядом лежит файл
`SHA256SUMS` с контрольными суммами. Выберите файл под своё устройство:

| Устройство | Файл |
|---|---|
| Linux на Intel или AMD (мини-ПК, NAS, VPS) | `fcd-<версия>-x86_64-unknown-linux-musl.tar.gz` |
| Linux на ARM64 (Raspberry Pi 3, 4, 5 с 64-битной системой, ARM-NAS) | `fcd-<версия>-aarch64-unknown-linux-musl.tar.gz` |
| Linux на ARMv7 с 32-битной системой (Raspberry Pi 2 и новее) | `fcd-<версия>-armv7-unknown-linux-musleabihf.tar.gz` |
| Mac с Apple Silicon (M1 и новее) | `fcd-<версия>-aarch64-apple-darwin.tar.gz` |
| Mac с Intel | `fcd-<версия>-x86_64-apple-darwin.tar.gz` |
| Windows (64 бита) | `fcd-<версия>-x86_64-pc-windows-msvc.zip` |
| Docker или Podman | образ `ghcr.io/stepin/fcd` (раздел [Docker](#docker)) |

Какой у вас процессор в Linux, показывает команда `uname -m`: `x86_64`, `aarch64` или `armv7l`. Сборки для Linux
статические: им не нужны библиотеки системы, подходит любой дистрибутив.

Проверка и распаковка (Linux и macOS):

```sh
sha256sum --check --ignore-missing SHA256SUMS
tar xzf fcd-<версия>-x86_64-unknown-linux-musl.tar.gz
sudo install fcd-<версия>-x86_64-unknown-linux-musl/fcd /usr/local/bin/fcd
fcd --version
```

На macOS вместо `sha256sum` есть `shasum -a 256 --check --ignore-missing SHA256SUMS`. Файлы не подписаны
сертификатом Apple; если macOS не даёт запустить скачанный `fcd`, снимите отметку о загрузке:
`xattr -d com.apple.quarantine fcd`.

### Сборка из исходного кода

Пока выпусков нет, сервер собирается из исходников. Нужны Node.js 22 или новее, pnpm 11 и Rust (stable).

```sh
pnpm install
pnpm build
cargo build --release --locked --manifest-path server/Cargo.toml
# готовый файл: server/target/release/fcd
```

Веб-приложение встраивается в `fcd`, поэтому `pnpm build` идёт первым. Архивы для других систем собирает
`scripts/release.sh` (подробности в [CONTRIBUTING.md](../CONTRIBUTING.md)).

## Первый запуск

```sh
fcd --data /var/lib/family-chat
```

`--data` это папка данных. При первом запуске сервер создаёт её и пишет в журнал (в терминал) примерно такое:

```
INFO fcd 1.0.1, папка данных /var/lib/family-chat
INFO слушаю 0.0.0.0:8787 (HTTP)
INFO откройте http://192.168.1.10:8787/ (приложение)
INFO откройте http://192.168.1.10:8787/server/ (проверка сервера)
INFO первый запуск: папка данных создана
INFO код администратора сервера: 7K3D-XXXX-XXXX-XXXX
INFO дальше: откройте приложение, нажмите «Настроить для своей семьи» и введите этот код
```

**Код администратора сервера** показывается один раз, сохраните его как пароль. Он многоразовый и нужен только для
одного: создавать семьи на этом сервере. Войти с ним в семью нельзя. Дальше:

1. Настройте HTTPS (следующий раздел) и откройте адрес сервера в браузере телефона или компьютера. Без HTTPS
   приложение работает только на том же компьютере по адресу `http://localhost:8787/`. Код сервера приложение
   отправляет только по HTTPS (или на этот же компьютер).
2. Нажмите «Настроить для своей семьи», введите адрес сервера и код.
3. Назовите себя, запишите 24 слова для восстановления (приложение проверит три из них) и создайте первое
   приглашение. На чистом сервере так настраивается корневая семья (по адресу самого сервера), а вы становитесь её
   администратором. Тот же код потом создаёт другие семьи на этом сервере ([Несколько семей на одном
   сервере](#несколько-семей-на-одном-сервере)).

Остановка: Ctrl+C или сигнал SIGTERM. Сервер дожидается открытых запросов не дольше 10 секунд. Второй экземпляр
на той же папке не запустится и скажет об этом.

### Два вида кодов

- **Код администратора сервера** один на весь сервер и многоразовый. Он только создаёт семьи (в приложении:
  «Настроить для своей семьи»). Новый код (старый перестаёт работать), при остановленном сервере:

  ```sh
  fcd reset-admin-code --data /var/lib/family-chat
  ```

  У сервера, который работал на версии 0.1.0, кода сервера нет: один раз выполните эту команду.
- **Код входа семьи** у каждой семьи свой и одноразовый: кто вошёл с ним, становится администратором этой семьи, и
  код перестаёт действовать. Это код настройки (его выдаёт создание семьи, он живёт 1 час) или код восстановления,
  если все администраторы семьи потеряли доступ:

  ```sh
  fcd families list --data /var/lib/family-chat          # id семей
  fcd reset-admin-code --data /var/lib/family-chat --family root     # корневая семья
  fcd reset-admin-code --data /var/lib/family-chat --family <id>     # другая семья
  ```

  Код восстановления вводят в приложении, как код администратора при входе в семью; участник семьи, вошедший с ним,
  становится администратором.

Родственники входят по приглашениям. «Настроить для своей семьи» первый экран показывает всегда, под кнопкой
написано, что нужен код от владельца сервера. Для проверки сервера сбрасывать код не нужно: администратор проверяет
сервер в приложении (раздел [Проверка сервера](#проверка-сервера)).

### Второй администратор

Администратор выпускает приглашения, отключает участников и видит место на диске. Сделать администратором ещё одного
участника можно командой при остановленном сервере:

```sh
fcd admin list --data /var/lib/family-chat
fcd admin add <userId> --data /var/lib/family-chat
```

`fcd admin list` показывает `userId`, имя и роль каждого участника. Без `--family` команды работают с корневой
семьёй, с `--family <id>` с другой семьёй этого сервера. Команды с `--family` тоже требуют остановленного сервера:
это останавливает все семьи сервера.

## Настройки

Каждую настройку можно задать тремя способами: флагом, переменной окружения или строкой в `config.toml` в папке
данных. Порядок: **флаг, затем переменная окружения, затем `config.toml`, затем значение по умолчанию**. Переменная
ведёт себя так же, как её флаг: оба важнее файла, а при первом запуске действующие значения (из флагов, переменных и
значений по умолчанию) записываются в новый `config.toml`; позже изменённые флаги и переменные туда не пишутся.
Пустая переменная считается незаданной. Логические значения: `true`, `false`, `1` или `0`; неверное значение
останавливает сервер с ошибкой, в которой названа переменная. После любых изменений перезапустите сервер.

| Флаг | Переменная окружения | В `config.toml` | По умолчанию | Что это |
|---|---|---|---|---|
| `--data` | `FCD_DATA` | | | папка данных (нужна для запуска; в образе Docker `/data`) |
| `--port` | `FCD_PORT` | `port` | `8787` | порт |
| `--listen` | `FCD_LISTEN` | `listen` | `0.0.0.0` | адрес; `127.0.0.1`, если прокси на том же компьютере |
| `--family-name` | `FCD_FAMILY_NAME` | `family_name` | `Семья` (по-английски `Family`) | имя корневой семьи, его видят все её участники |
| `--retention-days` | `FCD_RETENTION_DAYS` | `retention_days` | `90` | сколько дней сервер хранит сообщения и файлы (от 7 до 90) |
| `--max-file-mb` | `FCD_MAX_FILE_MB` | `max_file_mb` | `200` | предел размера одного файла, МБ |
| `--push` | `FCD_PUSH` | `push` | `true` | уведомления; `false`: сервер не обращается к push-сервисам (без токена Telegram ни к каким внешним адресам) |
| `--mcp` | `FCD_MCP` | `mcp` | `true` | подключение ИИ-помощников по MCP ([ИИ-помощники](#ии-помощники-mcp)); `false`: адрес `/mcp` и экран в приложении выключены |
| `--trust-forwarded-for` | `FCD_TRUST_FORWARDED_FOR` | `trust_forwarded_for` | `false` | брать адрес клиента из `X-Forwarded-For` (только за прокси) |
| `--lang` | `FCD_LANG` | `lang` | см. ниже | язык сообщений сервера: `ru` или `en` |
| `--tls-cert`, `--tls-key` | `FCD_TLS_CERT`, `FCD_TLS_KEY` | | | HTTPS со своими файлами сертификата (нужны оба) |
| `--web-dir` | `FCD_WEB_DIR` | | | отдавать приложение из папки (для разработки) |
| `--push-subject` | `FCD_PUSH_SUBJECT` | `push_subject` | `mailto:fcd-admin@example.org` | контакт для push-сервисов Apple, Google и Mozilla: `mailto:` или `https://` |
| `--min-free-mb` | `FCD_MIN_FREE_MB` | `min_free_mb` | `100` | когда свободного места меньше, МБ, сервер не принимает новое; `0`: не проверять |
| `--telegram-bot-token` | `FCD_TELEGRAM_BOT_TOKEN` | `telegram_bot_token` | | токен бота Telegram для наборов стикеров по ссылке ([Telegram](#telegram)); пусто: выключено |
| `--telegram-bot-token-file` | `FCD_TELEGRAM_BOT_TOKEN_FILE` | `telegram_bot_token_file` | | файл с токеном (секреты Docker и Podman) |
| `--telegram-api-url` | `FCD_TELEGRAM_API_URL` | `telegram_api_url` | `https://api.telegram.org` | адрес Bot API (свой telegram-bot-api) |
| `--telegram-api-allow-http` | `FCD_TELEGRAM_API_ALLOW_HTTP` | `telegram_api_allow_http` | `false` | разрешить `http://` в адресе Bot API не только для этого компьютера |

**Контакт для push-сервисов.** Адрес по умолчанию `mailto:fcd-admin@example.org` некоторые push-сервисы отклоняют.
Задайте свой: `--push-subject mailto:you@example.com` (или `FCD_PUSH_SUBJECT`, или `push_subject` в `config.toml`).
Неверное значение останавливает сервер с ошибкой, в которой названы источник и значение.

**`--offer-setup` удалён в 1.0.0.** Строку `offer_setup` из `config.toml` (её писала версия 0.1.0) удалите перед
запуском 1.0.0, иначе сервер и `fcd reset-admin-code` остановятся с ошибкой, которая называет эту строку.

Команды `healthcheck`, `reset-admin-code`, `families` и `admin` читают те же переменные, где они имеют смысл (`FCD_DATA`,
`FCD_PORT`, `FCD_LISTEN`, `FCD_LANG`). Другие имена `FCD_*` не мешают (`FCD_GIT_COMMIT` и `FCD_BIN` нужны сборке и
тестам).

**Язык.** Всё, что печатает сервер (строки при запуске, журнал, `fcd --help`, ошибки, `reset-admin-code`, `admin`,
`healthcheck`), бывает по-русски и по-английски: `--lang`, иначе `FCD_LANG`, иначе `lang` в `config.toml`, иначе
язык системы (`LC_ALL`, `LC_MESSAGES`, `LANG`), иначе русский. Несколько редких ошибок командной строки приходят из
библиотеки `clap` и остаются английскими.

Полный список с пояснениями: `fcd --help`. Подробный журнал: переменная окружения `RUST_LOG=debug`.

## Несколько семей на одном сервере

Один `fcd` держит несколько семей. Корневая семья отвечает по адресу самого сервера (`https://chat.example.org`),
каждая другая по своему адресу `https://chat.example.org/f/<id>` (`<id>` из 16 строчных букв и цифр). Для
приложения каждая такая семья как отдельный сервер: свой serverId, свои участники, приглашения
`https://chat.example.org/f/<id>/#invite=…`, свои администраторы и коды.

**Создать семью.** В приложении: «Настроить для своей семьи» (или «Добавить семью», «Я администратор: новая
семья»), адрес сервера, код администратора сервера, название семьи (на одном сервере названия разные без учёта
регистра). Приложение сразу входит в новую семью по её коду настройки, вы становитесь её администратором, а экран
«Готово» показывает адрес семьи и приглашение для родственников. Отдельного списка семей в приложении нет.

**Список семей:** `fcd families list --data …` показывает id, имя и состояние каждой семьи (настроена, не
настроена, сломана). Команда только читает и работает при запущенном сервере.

**Что общее, что своё.** Общие на весь сервер: порт и адрес, HTTPS, уведомления (вкл/выкл и `push_subject`), ключ
уведомлений `vapid.json`, срок хранения, предел файла, `min_free_mb`, токен Telegram, язык журнала, ограничение
частоты неверных кодов. Свои у семьи: serverId, название, код входа, администраторы, участники и все данные.

**Папка данных.** Корневая семья лежит в самой папке, как раньше. Другие семьи лежат в `families/<id>/` с той же
раскладкой, но без своих `fcd.lock`, `config.toml` и `vapid.json`. Сервер на папку семьи отдельно не запускают
(`fcd --data …/families/<id>` откажется и подскажет `--family`).

**Прокси** должен пропускать пути `/f/…`; примеры Caddy и nginx ниже проксируют весь `/`, этого достаточно.

**Сломанная семья.** Если у семьи не читается `server.json` или папка, сервер всё равно запускается: в журнале id
семьи и причина, а её адрес отвечает «семья временно недоступна» (503). Восстановите `families/<id>` из резервной
копии или вынесите папку из `families/` и перезапустите сервер. `fcd healthcheck` в этом случае по-прежнему
отвечает 0 (иначе контейнер со всеми семьями перезапускался бы), а сломанные семьи печатает предупреждением; с
`--strict` они дают код 1.

**Семья создана по ошибке:** остановите сервер, вынесите папку `families/<id>` (например, в резервные копии),
запустите сервер. Удаление семьи из приложения пока не предусмотрено.

**Затраты.** Каждая семья занимает свой поток записи и память на индексы своих данных. Замер на macOS (отладочная
сборка, 17.11.2026): сервер с одной семьёй занимает около 11 МБ памяти, с корневой и 20 пустыми семьями около 14 МБ,
запуск с 20 семьями меньше 0,1 секунды.

**Другой вариант:** второй `fcd` со своей папкой данных на своём адресе (поддомен или порт) по-прежнему работает.
Он полностью отделён, но нужен второй адрес и сертификат.

## Telegram

Наборы стикеров Telegram добавляются в приложении по ссылке `https://t.me/addstickers/<имя>`. Telegram отдаёт
наборы только через Bot API с токеном бота. Токен хранит сервер, к участникам семьи он не попадает. Видеостикеры
(`.webm`) пока пропускаются.

1. В Telegram откройте @BotFather, отправьте `/newbot`, задайте имя и получите токен вида `123456:ABC…`.
2. Передайте токен серверу одним из способов и перезапустите сервер:
   - переменная `FCD_TELEGRAM_BOT_TOKEN` (лучше всего в контейнере);
   - файл с токеном: `--telegram-bot-token-file /run/secrets/telegram_bot_token` (секреты Docker и Podman);
   - строка `telegram_bot_token = "…"` в `config.toml`;
   - флаг `--telegram-bot-token` (его значение видно в списке процессов, поэтому лучше другие способы).

   Docker:

   ```sh
   docker run -d --name fcd --restart unless-stopped \
     -p 127.0.0.1:8787:8787 -v fcd-data:/data \
     -e FCD_TELEGRAM_BOT_TOKEN=123456:ABC... \
     ghcr.io/stepin/fcd:latest
   ```

   compose (`environment:` у сервиса `fcd`): `FCD_TELEGRAM_BOT_TOKEN: "123456:ABC..."`. Podman Quadlet (в
   `[Container]`): `Environment=FCD_TELEGRAM_BOT_TOKEN=123456:ABC...` или `Secret=telegram_bot_token,type=env,target=FCD_TELEGRAM_BOT_TOKEN`.
   systemd: строка `FCD_TELEGRAM_BOT_TOKEN=123456:ABC...` в файле окружения сервиса.
3. При запуске сервер пишет одну строку: «Загрузка стикеров из Telegram: включена (бот @имя)», «токен отклонён
   Telegram» или «Telegram недоступен». Администратор видит то же в приложении: «Настройки», «Семья и сервер»; на
   странице `/server/` видно только «включено» или «выключено».

Токен: секрет, как пароль. Новый токен: правка и перезапуск; пустое значение выключает загрузку по ссылке. В новый
`config.toml` сервер токен не записывает и в журнал не выводит (в адресах запросов вместо него `bot***`). Если вы
записали токен в `config.toml`, он попадёт и в резервную копию.

С токеном сервер обращается к `api.telegram.org`: Telegram видит адрес сервера и имена наборов, которые загружают
участники. Свой сервер Bot API: `--telegram-api-url https://…` (`http://` только для этого компьютера или с
`--telegram-api-allow-http true`, например внутри сети compose). Режим `--local` у telegram-bot-api не
поддерживается.

Пределы (на весь сервер, все семьи вместе): не больше 20 запросов к Telegram в секунду и 2 одновременных загрузок
наборов; ожидание в очереди не дольше 15 секунд, затем ответ «Telegram просит подождать» (503 `telegram_busy`).
После ответа Telegram 429 весь сервер ждёт указанное время. На одно устройство: не больше 3 одновременных файлов и
300 запросов за 10 минут. У каждого запроса один срок 40 секунд, у отдельного обращения к Telegram 15 секунд.
Список набора хранится в памяти 10 минут (не больше 256 наборов). Файл: `.webp` до 512 КБ, `.tgs` до 128 КБ.

## HTTPS

Сервер слушает обычный HTTP. HTTPS даёт одно из двух: обратный прокси перед сервером (основной путь) или свои файлы
сертификата. Получать сертификат Let's Encrypt сам сервер не умеет.

### Обратный прокси

Прокси принимает HTTPS на вашем домене и пересылает запросы на `http://127.0.0.1:8787`. Что прокси должен
пропускать:

- **Долгие запросы.** Приложение ждёт новые сообщения в одном запросе до 30 секунд. Время ожидания ответа у прокси
  должно быть больше (например, 90 секунд), иначе связь будет постоянно рваться.
- **Тела до 5 МБ.** Файлы загружаются частями по 4 МиБ, каждая часть отдельным запросом.
- **Заголовок `X-Forwarded-For`**, чтобы ограничение частоты неверных кодов считало попытки по настоящим адресам.
  Тогда запускайте сервер с `--trust-forwarded-for true`. Без прокси этот флаг не включайте: заголовок может
  подделать кто угодно. За прокси без этой настройки все запросы приходят с адреса прокси, и неверные попытки входа
  и проверки сервера у всей семьи делят один счётчик (10 в минуту); поэтому за своим прокси её стоит включить.

Если прокси работает на том же компьютере, запускайте сервер с `--listen 127.0.0.1`, чтобы мимо прокси к нему
нельзя было обратиться. Прокси должен пропускать и пути `/f/…` (другие семьи этого сервера): примеры ниже
проксируют весь `/`.

**Caddy** сам получает и продлевает сертификат Let's Encrypt, если домен указывает на ваш адрес и порты 80 и 443
проброшены на компьютер с Caddy. По умолчанию он не ограничивает ни время ответа, ни размер тела, поэтому хватает
трёх строк:

```
chat.example.org {
	reverse_proxy 127.0.0.1:8787
}
```

**nginx** (сертификат, например, от certbot):

```nginx
server {
    listen 443 ssl;
    server_name chat.example.org;

    ssl_certificate     /etc/letsencrypt/live/chat.example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/chat.example.org/privkey.pem;

    # One request carries at most one 4 MiB part of a file.
    client_max_body_size 8m;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # New messages are awaited in one request for up to 30 seconds.
        proxy_read_timeout 90s;
        proxy_send_timeout 90s;
        proxy_buffering off;
        proxy_request_buffering off;
    }
}
```

Эти файлы лежат в репозитории: [deploy/caddy/Caddyfile](../deploy/caddy/Caddyfile),
[deploy/nginx/family-chat.conf](../deploy/nginx/family-chat.conf). Мы проверяли их чтением, но не запускали
против настоящего сервера.

**Другие варианты.** Обратный прокси в NAS (Synology, QNAP и другие) с сертификатом: назначение
`http://<адрес компьютера с fcd>:8787`. Cloudflare Tunnel: не нужен проброс портов, но HTTPS завершается у
Cloudflare, и Cloudflare видит запросы (переписка при этом остаётся зашифрованной). KeenDNS на роутерах Keenetic с
доменом на устройство в домашней сети: мы этот путь не проверяли. С любым вариантом проверьте долгий запрос на
странице [проверки сервера](#проверка-сервера).

### Свои файлы сертификата

Если сертификат у вас уже есть (например, его выпускает роутер или скрипт ACME):

```sh
fcd --data /var/lib/family-chat --tls-cert /path/fullchain.pem --tls-key /path/privkey.pem
```

- Сертификат: цепочка в PEM, сначала сертификат сервера. Ключ: PEM (PKCS#8, PKCS#1 или SEC1).
- С этими флагами порт отвечает только по HTTPS (TLS 1.2 и 1.3).
- Сертификат читается при запуске: после продления файлов перезапустите сервер.
- Порт 443 в Linux доступен только привилегированным программам. Проще оставить порт 8787 и пробросить на роутере
  внешний порт 443 на внутренний 8787.

## Docker

Образ содержит только `fcd` (пустой образ `scratch`), работает от пользователя 65534 и хранит данные в томе
`/data`. Проверка здоровья встроена: `fcd healthcheck`.

```sh
docker run -d --name fcd --restart unless-stopped \
  -p 127.0.0.1:8787:8787 -v fcd-data:/data \
  ghcr.io/stepin/fcd:latest
docker logs fcd 2>&1 | grep -E 'код администратора сервера|server admin code'
```

`latest` указывает на последний выпуск. Чтобы закрепить версию, берите тег версии, например
`ghcr.io/stepin/fcd:1.0.1` (теги те же, что на [странице выпусков](https://github.com/stepin/family-chat/releases),
без буквы `v`).

Настройки передаются переменными окружения, например `-e FCD_TRUST_FORWARDED_FOR=true` (флаги после имени образа
тоже работают: `... fcd:latest --trust-forwarded-for true`). Образ задаёт `FCD_DATA=/data`. Встроенная проверка
здоровья `fcd healthcheck` читает те же переменные, поэтому порт, изменённый через `-e FCD_PORT=...`, она тоже
знает; порт, изменённый флагом, нет, так что лучше переменная.

Именованный том (`fcd-data`) удобнее папки: Docker сам даёт ему нужного владельца. Если хотите папку на диске,
сделайте её владельцем пользователя 65534: `sudo chown 65534:65534 /srv/family-chat`.

Docker Compose, файл [compose.yaml](../compose.yaml) в корне репозитория:

```yaml
services:
  fcd:
    image: ghcr.io/stepin/fcd:latest
    restart: unless-stopped
    ports:
      - "127.0.0.1:8787:8787"
    volumes:
      - fcd-data:/data
    environment:
      # Server settings (fcd --help lists them all); the health check reads them too.
      FCD_LANG: "ru"
      # FCD_TRUST_FORWARDED_FOR: "true"
    stop_grace_period: 20s

volumes:
  fcd-data:
```

Команды сервера в контейнере (при остановленном сервере):

```sh
docker stop fcd
docker run --rm -v fcd-data:/data ghcr.io/stepin/fcd:latest reset-admin-code
docker start fcd
```

Образ собирается для `linux/amd64`, `linux/arm64` и `linux/arm/v7`.

## Podman Quadlet

Podman запускает контейнер как службу systemd по файлу `.container`. Для своего пользователя положите файл в
`~/.config/containers/systemd/fcd.container`, для всей системы в `/etc/containers/systemd/fcd.container`
([deploy/podman/fcd.container](../deploy/podman/fcd.container)):

```ini
[Unit]
Description=Family Chat server (fcd)

[Container]
Image=ghcr.io/stepin/fcd:latest
ContainerName=fcd
PublishPort=127.0.0.1:8787:8787
Volume=fcd-data:/data
AutoUpdate=registry
# Server settings (fcd --help lists them all); the health check reads them too.
Environment=FCD_LANG=ru
# Environment=FCD_TRUST_FORWARDED_FOR=true
HealthCmd=["/fcd", "healthcheck"]
HealthInterval=30s
HealthTimeout=15s
HealthStartPeriod=10s
HealthRetries=3

[Service]
Restart=always
TimeoutStopSec=20

[Install]
WantedBy=default.target
```

```sh
systemctl --user daemon-reload
systemctl --user start fcd
journalctl --user -u fcd | grep 'код администратора'
systemctl --user enable --now podman-auto-update.timer
```

`AutoUpdate=registry` вместе с таймером `podman-auto-update` раз в сутки проверяет, нет ли нового образа, и
перезапускает контейнер. `HealthCmd` записан массивом: в образе нет оболочки. Чтобы служба своего пользователя
работала без входа в систему, включите `loginctl enable-linger <пользователь>`. Этот файл мы не запускали: Podman
на машине подготовки не было.

Команды сервера в контейнере (при остановленном сервере). `podman exec` не подойдёт: в образе нет оболочки, а
сервер должен быть остановлен. Запускайте `podman run` от того же пользователя, что и службу: у rootless Podman и
у root свои тома, и под другим пользователем появится новый пустой том `fcd-data`.

```sh
systemctl --user stop fcd
podman run --rm -v fcd-data:/data -e FCD_LANG=ru ghcr.io/stepin/fcd:latest reset-admin-code
systemctl --user start fcd
```

Для файла в `/etc/containers/systemd/` те же команды через `sudo` и без `--user`.

## systemd без контейнера

Отдельный пользователь, папка данных и служба
([deploy/systemd/fcd.service](../deploy/systemd/fcd.service)):

```sh
sudo useradd --system --home-dir /var/lib/family-chat --shell /usr/sbin/nologin fcd
sudo install -d -o fcd -g fcd -m 700 /var/lib/family-chat
sudo install fcd /usr/local/bin/fcd
sudo cp fcd.service /etc/systemd/system/fcd.service
sudo systemctl daemon-reload
sudo systemctl enable --now fcd
sudo journalctl -u fcd | grep 'код администратора'
```

```ini
[Unit]
Description=Family Chat server (fcd)
After=network-online.target
Wants=network-online.target

[Service]
User=fcd
Group=fcd
Environment=FCD_DATA=/var/lib/family-chat
Environment=FCD_LISTEN=127.0.0.1
# More settings, one VARIABLE=value per line (fcd --help lists them all); the file may be absent.
EnvironmentFile=-/etc/family-chat/fcd.env
ExecStart=/usr/local/bin/fcd
Restart=on-failure
TimeoutStopSec=20
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
ReadWritePaths=/var/lib/family-chat

[Install]
WantedBy=multi-user.target
```

`FCD_LISTEN=127.0.0.1` подходит, если прокси на этом же компьютере; иначе уберите эту строку. Другие настройки
кладите в `/etc/family-chat/fcd.env`, по одной `FCD_...=значение` в строке. Команды при остановленной службе:
`sudo systemctl stop fcd`, затем `sudo -u fcd fcd reset-admin-code --data /var/lib/family-chat`, затем
`sudo systemctl start fcd`.

## Windows и macOS

На Windows распакуйте архив и запустите в терминале `fcd.exe --data C:\FamilyChat`, остановка: Ctrl+C. Службы
Windows в комплекте нет; для автозапуска подойдёт Планировщик заданий. На macOS
сервер запускается так же, как в Linux. На Windows папка данных защищена правами вашей учётной записи, отдельных
прав `0600` и `0700`, как в Linux и macOS, сервер не ставит.

## Обновление

Формат папки данных имеет номер версии. Новый сервер сам обновляет папку старой версии; старый сервер на папке
новой версии не запустится. Поэтому перед обновлением сделайте резервную копию (следующий раздел): откатиться можно
только к ней.

**С 0.1.0 на 1.0.0:** удалите строку `offer_setup` из `config.toml`, запустите 1.0.0 и один раз выполните
`fcd reset-admin-code` (при остановленном сервере), чтобы получить код администратора сервера для новых семей.
Корневая семья и её данные остаются как были.

- **Файл:** остановите сервер, замените `fcd`, запустите.
- **Docker:** `docker pull ghcr.io/stepin/fcd:latest`, затем удалите и создайте контейнер заново
  с тем же томом (`docker compose pull && docker compose up -d`).
- **Podman Quadlet:** обновляется сам (`AutoUpdate=registry`) или командой `podman auto-update`.

Приложение встроено в сервер, поэтому после обновления сервера у всех появится предложение обновить приложение.

## Резервная копия и восстановление

Всё, что хранит сервер, лежит в папке данных. Копия делается при **остановленном** сервере:

```sh
sudo systemctl stop fcd
sudo tar czf family-chat-$(date +%F).tar.gz -C /var/lib family-chat
sudo systemctl start fcd
```

Для Docker с томом `fcd-data`:

```sh
docker stop fcd
docker run --rm -v fcd-data:/data:ro -v "$PWD":/backup alpine tar czf /backup/fcd-data.tar.gz -C /data .
docker start fcd
```

Восстановление: остановите сервер, замените папку данных содержимым копии (с тем же владельцем), запустите. На
другом компьютере так же: копия переносит сервер целиком, вместе с адресами устройств и ключами уведомлений.

Копия папки данных включает все семьи сервера (папка `families/`). Если вы записали токен Telegram в
`config.toml`, он тоже в копии.

Что в копии: шифр сообщений и файлов, открытые ключи и профили участников (имена и фото профилей не шифруются),
кто в каком чате, ключ уведомлений `vapid.json`. Прочитать переписку по копии нельзя, но храните её так же бережно,
как саму папку. Исключение: если к семье подключены ИИ-помощники, в папке `mcp/` лежат ключи этих личностей, и по
копии их переписку прочитать можно ([ИИ-помощники](#ии-помощники-mcp)). Если удалить `vapid.json`, сервер создаст новые ключи, и уведомления на всех устройствах перестанут
приходить, пока каждый не включит их заново.

Копия сервера не заменяет архив на устройствах: сервер хранит не больше срока хранения, а более ранняя переписка
есть только на телефонах и в файлах архива ([памятка для семьи](FAMILY.md#архив-переписки)).

## Срок хранения и место на диске

- Сервер хранит сообщения, служебные записи и файлы не дольше `retention_days` дней (от 7 до 90). Раз в час и при
  запуске он удаляет целые дни, которые старше срока. Часы сервера, убежавшие вперёд, не стирают всё: отсчёт идёт
  от меньшего из «сейчас» и «самое новое событие плюс 7 дней».
- Не удаляются: участники, профили, аватары, записи чатов, состояние групп, ключи групп и наборы стикеров. Они
  маленькие, и без них восстановленное устройство не прочтёт переписку.
- Место определяют файлы. Пример: семья присылает 50 фото в день по 300 КБ, это около 1,3 ГБ за 90 дней.
- Когда свободного места меньше `min_free_mb` (по умолчанию 100 МБ), сервер отвечает «нет места» на новые сообщения,
  файлы и вступления; приложение покажет «На сервере семьи кончается место». Освободите место или уменьшите срок
  хранения.
- Занятое и свободное место видно администратору в приложении: «Настройки», «Семья и сервер».

## Участники

- **Приглашение** выпускает администратор: «Настройки», «Семья и сервер», «Приглашения». Каждое действует для одного
  человека 7 дней и работает один раз. Отозванное приглашение перестаёт действовать сразу.
- **Отключить участника** можно там же. Его устройства сразу перестают получать и отправлять сообщения; уже
  полученная переписка остаётся у всех. Владельцы групп, где он был, получают об этом служебное сообщение.
- Неверные коды и подписи ограничены: не больше 10 ошибок в минуту с одного адреса, общие для всех семей сервера
  (вместе с неверными кодами администратора сервера).

## ИИ-помощники (MCP)

К семье можно подключить ИИ-помощника, например Claude: он читает и пишет сообщения по протоколу MCP. Всё встроено в
`fcd`, ставить ничего не нужно. Как подключить, что помощнику разрешено и чего он не может: [MCP.md](MCP.md).

- **Кто подключает.** Администратор семьи создаёт помощников (отдельные участники со своей личностью) в приложении:
  «Настройки», «ИИ-помощники». Любой участник там же может подключить помощника к своей личности. Команд `fcd` для
  этого нет: подключениями управляют в приложении при работающем сервере.
- **Что меняется для сервера.** Для подключённых личностей, и только для них, сервер хранит ключи (папка `mcp/` в
  данных семьи) и может читать их переписку. Пока подключений нет, ключей на сервере нет
  ([безопасность](SECURITY-MODEL.md#ии-помощники-mcp)).
- **Адрес.** `https://<ваш сервер>/mcp`, у семьи по адресу `/f/<id>`: `https://<ваш сервер>/f/<id>/mcp`. Отдельный
  порт не нужен.
- **Прокси.** Запросы ожидания длятся до 50 секунд: время ожидания ответа должно быть больше (проверка «длинный
  запрос» ниже показывает, проходят ли 25 секунд). Прокси должен передавать `Host` и `X-Forwarded-Proto`: из них
  сервер строит одноразовые ссылки на файлы. Для ограничения неверных токенов по адресу клиента за прокси нужен
  `trust_forwarded_for = true`, как и для кодов.
- **Выключить.** `mcp = false` в `config.toml` (или `--mcp false`, `FCD_MCP=false`) и перезапуск. Подключения
  остаются на диске; чтобы стереть ключи, удалите подключения в приложении до выключения или удалите папку `mcp/`
  при остановленном сервере (помощники тогда останутся в списке участников, исключите их в приложении).
- **Журнал.** Сервер пишет, какое подключение какой инструмент вызвало, без аргументов и текста сообщений;
  чтение видно при `RUST_LOG=debug`.

## Проверка сервера

Две проверки показывают, всё ли в порядке между телефоном и сервером: **длинный запрос** (проходит ли ожидание 25
секунд через ваш прокси или туннель; если запрос рвётся раньше, увеличьте время ожидания у прокси) и **пробное
уведомление** (доходят ли уведомления до этого телефона). Проверки работают всегда, флаги для них не нужны.

- **До настройки**, пока корневая семья не настроена: страница `https://<ваш сервер>/server/` с кодом
  администратора сервера (или кодом входа семьи). Там же видно, что сервер отвечает: имя семьи, версия, срок
  хранения, расхождение часов, Telegram. Другая семья проверяется на своей странице `https://<ваш сервер>/f/<id>/server/`.
- **После настройки**: в приложении у администратора, «Настройки» → «Семья и сервер» → «Проверка сервера». Код
  администратора к этому времени уже использован, приложение проверяет сервер своим входом. Обычный участник
  раздела не видит; в его «Диагностике» написано, что проверку делает администратор.

На странице `/server/` после входа администратора код уже не подходит, и страница говорит, где теперь проверки.
Неверные коды считаются вместе с попытками входа (10 в минуту с одного адреса). Если уведомление не пришло, строки
журнала сервера `test push sent` и `delayed test push failed` показывают, что ответил push-сервис.

Есть и страница проверки устройства `/device/`: что умеет браузер этого телефона.

## Как убедиться, что сервер жив

`fcd healthcheck` спрашивает сервер на этом же компьютере и завершается с кодом 0, если он отвечает, и 1, если нет.
Порт берётся из флага `--port` или из `config.toml` в `--data`, работает и с `--tls-cert`:

```sh
fcd healthcheck --data /var/lib/family-chat
```

Сломанные семьи (см. [Несколько семей](#несколько-семей-на-одном-сервере)) печатаются предупреждением и на код
