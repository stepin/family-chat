# Изменения

Формат: разделы по версиям, новые сверху. Нумерация версий [SemVer](https://semver.org/lang/ru/); до 1.0 формат
данных и API могут меняться, но сервер обновляет папку данных старой версии сам.

## [0.1.0] (не выпущена)

Первая версия. Собрана по этапам M1-M6 плана (`docs/PLAN-v2.md`).

### Что есть

- **Сервер `fcd`** (M1-M5): один исполняемый файл на Rust с встроенным веб-приложением, папка данных без базы данных,
  журнал событий по дням с `fsync`, очистка по сроку хранения (7-90 дней), одноразовые приглашения, вход
  устройств подписью ключа, длинный запрос, Web Push (RFC 8291, VAPID) без внешних библиотек push, ограничение
  частоты неверных кодов, HTTPS со своими файлами сертификата, заголовки безопасности, ответ 507 при нехватке места.
- **Личные чаты** (M1): вступление по приглашению, личность из 24 слов, сквозное шифрование, черновики, диагностика,
  PWA, маршрут приглашённого на iPhone.
- **Группы, вложения, архив** (M2): владелец, эпохи и запечатанные ключи, профили и аватары, отзыв идентичности,
  фото и файлы частями по 4 МиБ, уведомления, экспорт и импорт архива `.fcarchive`, исключение участника,
  экран сервера.
- **Большие файлы, голосовые, место** (M3): файлы до 200 МБ потоком, голосовые до 10 минут, место без карты.
- **Переписка** (M4): ответ, правка, удаление у всех, реакции, эмодзи, пересылка, поиск на устройстве.
- **Несколько семей** (M5): несколько серверов в одном приложении, стикеры (без шифрования, по плану), счётчик на
  значке, «Поделиться» из других приложений (Web Share Target), связывание личностей.
- **Публикация** (M6):
  - сайт проекта (`apps/site`): главная, установка, памятка для семьи, безопасность, вопросы, протокол и API,
    русский и английский, снимки экрана с настоящего сервера, веб-приложение в `app/`; без скриптов и без
    обращений к другим сайтам;
  - документация для администратора и семьи (`docs/ADMIN.md`, `docs/FAMILY.md`, `docs/SECURITY-MODEL.md`,
    `docs/FAQ.md` и английские версии в `docs/en/`), `CONTRIBUTING.md`, `SECURITY.md`, `docs/RELEASING.md`;
  - `fcd healthcheck` (проверка здоровья для контейнеров), `fcd admin list`, версия с коммитом в
    `fcd --version`, `/v1/hello` (поле `commit`) и в приложении;
  - свободное место на диске под Windows (раньше проверка 507 там не работала), остановка по закрытию консоли
    Windows;
  - приложение после перезапуска сразу показывает «На связи» (первый запрос событий не ждёт 25 секунд), пузыри
    сообщений на телефоне больше не оставляют пустую строку под широким сообщением;
  - сборка выпуска `scripts/release.sh` (архивы с `SHA256SUMS`, воспроизводимые метки времени), workflow
    выпуска, сайта и проверки под Windows, образ Docker для нескольких архитектур с кросс-компиляцией, примеры
    для Docker Compose, Podman Quadlet, systemd, Caddy и nginx.

- **Доработки по ручной проверке** (M7):
  - два языка, русский и английский, в приложении (выбор «Язык» в настройках: как в системе, русский, English;
    смена сразу, без перезагрузки; грузится только нужный язык), в уведомлениях, на страницах проверки `/device/`
    и `/server/` и в сервере (`--lang`, `FCD_LANG`, `lang` в `config.toml`, переменные `LC_ALL`, `LC_MESSAGES`,
    `LANG`; по умолчанию русский): строки при запуске, журнал, `fcd --help`, ошибки, `reset-admin-code`, `admin`,
    `healthcheck`;
  - пол в профиле (М или Ж, по умолчанию М): необязательное подписанное поле `gender`, профили до M7 действительны
    без изменений; служебные строки групп, отметки и подсказки согласуются с полом;
  - «Оформление»: тема (как в системе, светлая, тёмная), шесть цветовых схем, размер текста в чатах, углы сообщений,
    фон чата, кнопка «Сбросить»; применяется до первой отрисовки, без вспышки;
  - эмодзи: выбор закрывает окно; в пустое поле эмодзи сразу уходит сообщением (как ответ, если он набирается),
    иначе встаёт на место курсора, в том числе на телефоне; при правке только вставляется;
  - вверху экрана больше нет имени семьи: при одной семье заголовок «Чаты» и свой аватар (открывает настройки), при
    нескольких компактный значок семьи; имя семьи в уведомлениях только при нескольких семьях;
  - приглашения: «Создать ещё одно приглашение», понятно, что одно приглашение для одного человека;
  - настройки сервера переменными окружения `FCD_*` (порядок: флаг, переменная, `config.toml`, значение по
    умолчанию), их же читает `fcd healthcheck`; примеры для Docker Compose, Podman и systemd на переменных.

### Что проверено при подготовке

Тесты сервера, протокола, ядра, приложения и сайта проходят на macOS (Apple Silicon); в CI они настроены на Linux.

| Сборка | Как проверена |
|---|---|
| `aarch64-apple-darwin` | собрана `scripts/release.sh`, запущена: `--version`, старт, `/v1/hello`, приложение на `/`, `healthcheck`, остановка по SIGTERM |
| `x86_64-apple-darwin` | собрана (`cargo build --release`), запущена через Rosetta 2: только `--version` |
| `x86_64-unknown-linux-musl` | собрана `scripts/release.sh` (cargo-zigbuild), запущена в Linux (эмуляция x86_64 в arm64-VM): `--version`, старт, `/v1/hello`, `healthcheck`, остановка по SIGTERM |
| `aarch64-unknown-linux-musl` | собрана `scripts/release.sh` (cargo-zigbuild), запущена в Linux arm64: `--version`, старт, `healthcheck`, `/`, остановка по SIGTERM |
| `armv7-unknown-linux-musleabihf` | собрана `scripts/release.sh` (cargo-zigbuild), не запускалась (на машине сборки нет 32-битного ARM) |
| `x86_64-pc-windows-msvc` | локально не собиралась; собирается и проходит пробный запуск в workflow выпуска на Windows |
| `x86_64-pc-windows-gnu` | собрана (cargo-zigbuild), `cargo clippy --all-targets` чистый; не запускалась |
| `mipsel-unknown-linux-musl` | не собиралась: цель третьего уровня, готовой стандартной библиотеки в rustup нет |
| образ `linux/amd64` | собран кросс-компиляцией, запущен: `/v1/hello`, приложение на `/`, статус `healthy`, остановка по SIGTERM |
| образ `linux/arm64` | собран кросс-компиляцией, не запускался |
| образ `linux/arm/v7` | при подготовке не собран: на машине сборки кончилось место |

На настоящих роутерах, NAS и одноплатных компьютерах сервер не запускался. Доставка уведомлений через настоящие
push-сервисы Apple, Google и Mozilla в автоматических тестах не проверяется.
